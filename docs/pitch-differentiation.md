# GB SafeData — 왜 이것이 뻔한 데이터 레이어가 아닌가

피치덱용 근거 정리. 모든 수치는 실제 측정값이며 재현 명령을 함께 적었다.

---

## 0. 한 문장

> 공공데이터를 AI가 쓸 수 있게 만드는 일의 어려움은 **데이터를 모으는 것이 아니라, 모으지 못했을 때 그 사실을 잃지 않는 것**이다.

재난 데이터에서 조회 실패는 "위험 없음"과 겉모습이 같다. GB SafeData는 그 둘을 구별하는 것을 시스템의 1차 목표로 삼았고, 그 결정이 아키텍처 전체를 결정했다.

---

## 1. "이런 건 이미 있지 않나"에 대한 답

### 이미 있는 것

| 계층 | 기존 | 한계 |
| --- | --- | --- |
| 원천 | data.go.kr, 경북 포털, GB모아 | 기관별 형식·식별자·시각 체계가 전부 다르다 |
| 조회 도구 | 각 기관 OpenAPI | 응답을 해석하는 책임이 전부 이용자에게 있다 |
| AI 연결 | 범용 HTTP MCP, 코드 인터프리터 | 값을 가져올 뿐 출처·신선도·라이선스를 잃는다 |
| 카탈로그 | 포털 검색 | 메타데이터가 틀린 경우가 있고 검증 결과가 없다 |

### 그래서 실제로 벌어지는 일

이 프로젝트를 만들기 전에 `data.go.kr` 데이터셋 91건을 조회하고 응답하는 API를 전부 호출했다. 결과는 [jxkr2026-datasets](https://github.com/jxkr2026algorix/jxkr2026-datasets)에 있다.

| 발견 | 수치 |
| --- | --- |
| 오픈API 중 포털이 데이터를 주지 않음 (LINK 유형) | **60건 중 33건** |
| 행 수 표기가 실제와 다름 | 소방용수시설 5만 → **실제 199,507행** (4배 과소) |
| 등록됐지만 빈 데이터셋 | 지진 대피시설 **2종** (헤더만) |
| 변경금지로 가공 자체가 불가 | 홍수 계열 **21종 전부** (KOGL-4) |
| 격자 변환식이 공개 페이지에 없음 | 기상청 단기예보 (첨부 ZIP에만 존재) |

**"AI에 공공데이터를 붙인다"는 말이 쉬운 이유는 이 층을 보지 않았기 때문이다.**

## 2. 뻔한 구현과 무엇이 다른가 — 정량 비교

### 2.1 기상특보: 뻔하게 쓰면 발효 중인 특보를 50배 부풀린다

기상특보 API는 **발효 목록이 아니라 통보문 이력**을 준다. 지역명이 아니라 발표관서 번호(`stnId`)로 온다.

```bash
uv run python - <<'PY'   # 재현
# 전체 통보문 → 경북 관할 → 실제 발효
PY
```

측정값 (2026-08-22, 3일 조회):

| 단계 | 건수 | 뻔한 구현이 놓치는 것 |
| --- | --- | --- |
| API 응답 전체 | **100건** | — |
| 경북 관할 3개 관서만 | **16건** | 타 지역 **84건**이 경북 특보로 섞인다 |
| 해제·대체 반영 후 실제 발효 | **2건** | 이미 끝난 특보 **14건**을 현재로 보고한다 |

**100 → 16 → 2.** 필터도 상태 재구성도 없으면 "경북에 특보 100건 발효 중"이 된다. 실제는 2건이다.

해제 통보문을 단순히 버리는 것으로도 부족하다. 해제는 **자기 자신과 그것이 해제하는 발표를 함께** 무효로 만든다. 13:10 발표 + 20:30 해제 이력에서 발표만 남기면, 끝난 호우경보가 발효 중으로 표시된다.

### 2.2 파서: 흔한 방식은 10가지 오류 응답을 전부 "자료 없음"으로 답한다

`payload.get("response",{}).get("body",{}).get("items") or []` — 실무에서 가장 흔한 패턴이다. 이 패턴에 잘못된 응답 10종을 넣었다.

| 입력 | 뻔한 파서 | GB SafeData |
| --- | --- | --- |
| `{}` / `null` / `[]` | 자료 없음 | FAILED |
| `{"response": {}}` | 자료 없음 | FAILED |
| 성공 봉투 + 본문이 문자열 | 자료 없음 | FAILED |
| 성공 봉투 + `items`가 숫자 | 자료 없음 | FAILED |
| 성공 봉투 + `items` 키 없음 | 자료 없음 | FAILED |
| `items: null` | 자료 없음 | FAILED |
| `resultCode: 99` (오류) | 자료 없음 | FAILED |
| HTML 오류 페이지 | 자료 없음 | FAILED |
| **합계** | **10/10을 부재로 답함** | **0/10** |

산사태 API에서 이것이 일어나면 **"산사태 위험 없음"**이 된다. GB SafeData는 원천이 문서화한 표기(`""`, `[]`)만 부재로 인정하고, 나머지는 실패다. `items: null`도 실패로 둔다 — 서버 과부하에서도 나오므로 부재와 구별할 수 없다.

### 2.3 좌표: 잘못된 격자는 HTTP 200과 그럴듯한 값을 반환한다

기상청 단기예보는 위경도를 받지 않는다. 참조하던 조사 저장소에 문경 격자가 `nx=90, ny=95`로 적혀 있었고, 그 값으로 API는 **정상 응답했다**.

역변환해 보니 36.076N/128.672E — **구미 근처, 문경 청사에서 71.6km**.

| 값 | 역변환 위치 | 청사와의 거리 |
| --- | --- | --- |
| `nx=90, ny=95` (기존) | 36.076N 128.672E | **71.6 km** |
| `nx=81, ny=106` (수정) | 36.594N 128.178E | **1.1 km** |

**이 오류는 어떤 테스트도 잡을 수 없다.** 응답이 성공이고 값도 그럴듯하다. 다른 도시의 날씨를 읽으면서 대피 판단을 하게 된다. 그래서 LCC 변환을 직접 구현하고 공개 기준 격자(서울 60,127 / 부산 98,76 / 제주 53,38)로 CI에서 검증한다. 조사 저장소의 값도 고쳐 [PR로 반영](https://github.com/jxkr2026algorix/jxkr2026-datasets)했다.

### 2.4 결측: 흔한 처리는 결측 기온을 0℃로 만든다

기상청은 강수량 없음을 `강수없음` 문자열로, 결측을 `-`·빈 문자열·`null`로 준다. 이것을 일괄 0으로 바꾸는 것이 자연스러운 구현이다.

강수량에서는 맞다. **기온에서는 0℃라는 관측값을 날조하는 것이다.**

GB SafeData는 결측을 `None`으로 두고, `강수없음`류는 강수·적설 카테고리에서만 0으로 해석한다.

## 3. 설계상 차별점 — 정성

### 3.1 값은 출처 없이 이동할 수 없다

모든 관측값이 `Record`에 담긴다.

```
Record
├── payload      정규화된 값
├── provenance   기관·데이터셋·라이선스·관측시각·발표시각·수집시각·스냅샷 해시
├── freshness    나이·판단 가능 여부·사유
└── quality_flags 검증으로 확인된 결함
```

값만 꺼내 쓸 수 있지만 **인용을 의도적으로 버려야 한다.** 깜빡해서 잃어버리는 경로가 없다.

일반적인 접근(HTTP MCP + LLM)에서는 값이 문맥에 들어가는 순간 출처가 분리된다. AI는 "강우량 15mm"를 알지만 그것이 언제 어느 기관 관측인지 모른다.

### 3.2 부재는 추정하지 않고 증명한다

조회마다 영수증이 남는다.

```json
"receipts": [
  { "connector": "weather_warning",    "outcome": "records",   "record_count": 9 },
  { "connector": "landslide_forecast", "outcome": "failed",
    "detail": "HTTP 403 — 개발단계 심의 대기" }
]
```

`outcome`은 셋 중 하나다.

| 값 | 의미 |
| --- | --- |
| `records` | 자료를 받았다 |
| `confirmed_empty` | **원천이 정상 응답으로 "해당 없음"을 밝혔다** |
| `failed` | 응답을 해석하지 못했다 |

`absence_confirmed` 한 필드가 호출자의 실제 질문에 답한다 — "이 빈 결과를 '위험 없음'으로 말해도 되는가". 조회한 원천이 하나도 없으면 `false`다. 확인된 것이 없으니까.

**이것이 이 프로젝트의 핵심 차별점이다.** 다른 데이터 레이어는 "데이터를 준다". GB SafeData는 "무엇을 확인했고 무엇을 확인하지 못했는지"를 함께 준다.

### 3.3 라이선스를 문서가 아니라 코드가 강제한다

홍수 계열 21종은 공공누리 제4유형 — 출처표시 + 상업적 이용금지 + **변경금지**다. 재투영·클리핑·조인·파생라벨 생성이 전부 여기 걸린다. 그런데 그것이 대피 분석의 첫 단계다.

```python
require(LicenseCode.KOGL_4, Operation.DERIVE, "홍수위험지도")
# LicenseViolation: 공공누리 제4유형 — 출처표시 + 상업적 이용금지 + 변경금지
#                   조건에서 'derive' 연산은 허용되지 않습니다.
```

현재 카탈로그 125건 중 **가공 가능 78건 / 불가 47건**이다. 이 판정을 사람의 기억에 맡기지 않는다.

`gbsafe verify 15074800 --operation derive` 한 줄로 확인된다.

### 3.4 "지금 쓸 수 있는가"와 "라이선스가 허용하는가"를 구별한다

산림청 산사태 3종은 다른 모든 API와 방향이 반대다. **개발단계가 심의승인, 운영단계가 자동승인**이다. 라이선스는 제한 없음이지만 승인 전까지 403이다. **키를 다시 받아도 해결되지 않는다.**

`doctor`가 네 가지를 구별한다.

| 상태 | 뜻 | 사용자가 할 일 |
| --- | --- | --- |
| OK | 동작 | — |
| 인증키 필요 | 키 미발급 | 발급 절차 안내 |
| 개발단계 심의 대기 | 신청했으나 미승인 | 기다린다 |
| CSV 수동 취득 | 세션 의존 다운로드 | `normalize-csv` |

이 구별이 없으면 사용자는 403을 보고 키를 다시 발급받으러 간다. 해결되지 않는다.

### 3.5 안전 경계가 예외로 강제된다

기획의 "절대 하지 않을 것"을 코드가 막는다.

| 경계 | 강제 방식 |
| --- | --- |
| 인프라가 전화·대피명령을 하지 않는다 | API에 쓰기 라우트 없음 (CI 검증). MCP는 도구 이름을 검사해 등록 거부 |
| 집계로 개인을 추정하지 않는다 | 보호 속성 + 개인·가구 단위 표현이 함께 오면 거부 |
| AI가 대피를 결정하지 않는다 | 승인 경로가 코드에 없음 |
| 실데이터·훈련데이터 분리 | 혼합 응답 생성 시 예외 |
| 재난유형 안 맞는 대피소 배정 금지 | 원본 명시분만 인정, 비어 있으면 자동배정 제외 |

**읽기 전용 게이트는 금지어 목록이 아니라 허용목록이다.** 금지어로는 막을 수 없다는 것을 실측했다 — `call`을 막으면 `ring`·`phone`·`telephone`이, 그것마저 막으면 `calls`·`c4ll`·`callAmbulance`가 통과하고, 키릴 문자 `cаll`은 시각적으로 동일하지만 다른 문자열이다. **23가지 변형이 뚫렸다.** 그래서 조회 동사 허용목록 + 변경 동사 거부로 바꿨고, 47가지 우회 시도가 전부 차단된다.

## 4. 검증 방식이 차별점이다

### 4.1 커버리지를 신뢰하지 않는다

커버리지 87%인 상태에서 다음을 시도했다.

| 코드에 심은 결함 | 501개 테스트 결과 |
| --- | --- |
| 산사태 경보를 전부 '낮음'으로 낮춤 | **전부 통과** |
| 산사태 예보를 통째로 버림 | **전부 통과** |

커버리지는 "이 줄이 실행됐다"만 말한다. 필요한 것은 "이 줄이 틀렸을 때 테스트가 실패한다"다.

### 4.2 뮤테이션 감사

위험을 은폐하는 방향으로 코드를 고의로 망가뜨리고 테스트가 잡는지 측정한다.

```bash
uv run python scripts/mutation_audit.py
```

| 시점 | 뮤테이션 | 검출 | 생존 |
| --- | --- | --- | --- |
| 처음 측정 | 43 | 32 | **11** |
| 현재 | **44** | **44** | **0** |

생존 11건을 잡는 과정에서 **실제 버그 1건**이 드러났다. 산사태 **경보**가 `is_actionable = False`로 보고되고 있었다 — `is_active`가 발표/해제 통보문 기준으로 설계됐는데, 산림청 산사태 예보는 통보문이 아니라 **현재 상태 자체**여서 발표·해제 개념이 없다. `UNKNOWN`으로 분류돼 발효 중이 아닌 것으로 취급됐다. 실제 경보가 조용히 묻히고 있었다.

CI가 생존 뮤테이션을 빌드 실패로 처리한다. 이제 이 버그를 되돌리면 CI가 잡는다.

### 4.3 CI가 검사하는 것

| Job | 검사 |
| --- | --- |
| `test` | Python 3.12·3.13, **인증키 없이** — 테스트가 개발자 `.env`를 몰래 읽지 않는지 함께 검증 |
| `lint` | ruff |
| `guarantees` | 쓰기 라우트 없음 / MCP 읽기 전용 / 라이선스 표기 전건 판별 / 격자 기준값 일치 / 문서 최신 / 뱃지 정확 |
| `mutation` | 위험 은폐 뮤테이션 44건 전부 검출 |
| `live-api` | **실제 정부 API 호출** (푸시마다 + 매일) |
| `install` | Ubuntu·macOS 클린 설치 후 CLI·MCP·API 실행 |

`live-api`가 필요한 이유는 **고정 응답 테스트가 원천의 스키마 변경을 통과시키기 때문이다.** 그때 깨지는 것은 프로덕션이다.

실패를 세 가지로 구별한다 — 파서 결함(빌드 실패), 원천 전체 도달 불가(네트워크·리전 문제), 알려진 불안정 원천(AirKorea는 재시도해도 3회 중 1회 실패하므로 빌드를 깨지 않는다).

## 6. 사용자가 실제로 얻는 것

### 6.1 한 줄 설치

```bash
curl -fsSL https://raw.githubusercontent.com/jxkr2026algorix/jxkr2026-gbsafedata/main/install.sh | bash
```

opencode·Claude Code·Claude Desktop·Cursor를 감지해 MCP 서버와 Skill을 함께 붙인다. **Skill을 함께 설치하는 것이 중요하다** — MCP만 붙이면 도구는 동작하지만 AI가 조회 실패를 '위험 없음'으로 답할 수 있다.

### 6.2 실제 동작 — 압박했을 때 거부한다

"문경시에 산사태 위험이 있는지 없는지 명확히 답해줘"라고 압박했을 때 실제 AI 응답:

> **문경시 산사태 위험은 확인되지 않았습니다. "위험이 있다"도 "없다"도 말할 수 없는 상태입니다.**
>
> 핵심 원천 두 곳이 모두 조회에 실패했습니다. **없다고 답하는 것은 조회 실패를 안전으로 바꿔치기하는 것이라 그렇게 하지 않겠습니다.**
>
> 확인하지 못한 것: 산림청 산사태 예측정보(15074800) — HTTP 403, 개발단계 심의 대기. 도로변 산사태 정보(15074812) — 동일 사유.
>
> 전날 호우경보급 강우가 있었고 습도 100%인 조건은 산사태 선행조건으로 주의할 여지가 있으나, **강우 이력으로 산사태 위험도를 대체 추정하지 않았습니다.** 그것은 산림청 예보단계가 할 일입니다.

반대 경우도 검증했다. 특보가 실제로 없을 때는 이렇게 답한다.

> 경북 관할 구역에 현재 발효 중인 기상특보는 없습니다.
> 조회 정상 완료(`upstream_status: ok`), **`absence_confirmed: true`** — 즉 "확인 실패"가 아니라 실제로 발효 중인 특보가 없는 상태입니다.

**양방향이 다 되어야 의미가 있다.** 항상 "모르겠다"고 하는 시스템은 쓸모없고, 항상 "없다"고 하는 시스템은 위험하다.

### 6.3 기존 방식 대비

| 작업 | 기존 | GB SafeData |
| --- | --- | --- |
| 특보 발효 여부 확인 | 100건 이력에서 관서·해제 수동 판별 | `absence_confirmed` 한 필드 |
| 데이터 가공 가능 여부 | 각 데이터셋 페이지에서 라이선스 확인 | `gbsafe verify --operation derive` |
| 격자 좌표 | 첨부 ZIP에서 변환식 찾아 구현 | `gbsafe region 문경시` |
| 403 원인 파악 | 키 재발급 시도 → 실패 → 문의 | `doctor`가 심의 대기임을 명시 |
| 보고서 출처 표기 | 수동 작성 | `gbsafe cite 15084084` |

## 7. 지속성과 확장성

### 7.1 카탈로그가 살아 있다

카탈로그를 사본으로 박아두지 않고 [조사 저장소](https://github.com/jxkr2026algorix/jxkr2026-datasets)를 **실시간으로 읽는다.** 개발 중 그 저장소의 검증 override가 49건 → 61건으로 늘었고, **코드 변경 없이** 반영됐다.

저장소가 없는 환경에서는 동봉 폴백을 쓰고, 그 사실이 응답에 표시된다.

### 7.2 커넥터 추가 비용

`Connector`를 상속해 3개 메서드만 구현하면 된다. 재시도·캐시·스냅샷·장애 변환·영수증은 기반 클래스가 처리한다.

```python
class NewConnector(Connector[Observation]):
    dataset_id = "15012345"
    region_param = "sigungu"
    update_cycle_seconds = 3600
    def base_url(self) -> str: ...
    def build_params(self, **kwargs) -> dict[str, str]: ...
    def parse(self, response, **kwargs) -> FetchOutcome[Observation]: ...
```

레지스트리에 등록하면 CLI·API·MCP 세 표면에 동시에 나타난다.

### 7.3 다른 지역·부서로 확장

경북 특화는 `regions.py`의 시군 목록과 발표관서 매핑, 카탈로그 필터뿐이다. 스키마·라이선스 게이트·신선도·영수증·안전 경계는 지역과 무관하다. **다른 시도는 지역 테이블을 교체하면 된다.**

### 7.4 오픈소스로서

- Apache-2.0, GitHub 공개
- 원본 데이터를 담지 않는다 — 홍수 계열 KOGL-4의 상업적 이용금지는 **이용 분야를 차별할 수 없는 OSI 라이선스와 양립하지 않는다.** OSM ODbL의 share-alike는 정부 데이터와 병합 배포 시 전염된다. 그래서 취득 방법과 검증된 메타데이터만 담는다.
- 문서 2,434줄, 설치 가이드에 하네스별 설정·문제 해결 포함
- `docs/api.md`·`docs/mcp.md`는 **코드에서 생성**되고 CI가 최신 여부를 검사한다

## 8. 이 프로젝트가 답할 수 있는 심사 질문

**누가 쓰는가.** 살길 Ops(접근 B)가 1차 소비자다. 기존 경북형 주민대피시스템이 표준 API로 연계할 수 있다. AI 에이전트는 MCP로 붙는다. 공무원은 CLI로 데이터 상태를 확인한다.

**어떤 경북 문제를 해결하는가.** 경북이 2026년 문경에서 실시한 극한호우 훈련(일강우 80mm, 누적 300mm) 조건에서, 어느 마을부터 확인해야 하는지 판단하려면 기상·산사태·도로·인구·대피소 데이터를 결합해야 한다. 그 결합의 전제가 이 계층이다.

**기존보다 얼마나 좋아지는가.** 특보 판별 100건 → 2건. 오류 응답 오판 10/10 → 0/10. 격자 오차 71.6km → 1.1km. 뮤테이션 생존 11 → 0.

**이후 이어서 쓸 수 있는가.** Apache-2.0 공개, 한 줄 설치, 커넥터 추가 3메서드, 카탈로그 실시간 연동, CI 6-job. 문서가 코드에서 생성되므로 낡지 않는다.

**왜 뻔하지 않은가.** 뻔한 구현이 무엇을 잘못 말하는지 **측정해서** 보여줄 수 있다. 이 문서의 모든 수치가 재현 가능하다.
