# 경북 재난 공공데이터 안전 사용

재난 데이터는 틀렸을 때의 대가가 크다. 이 스킬은 그 대가를 줄이는 규칙을 담는다.

## 이 스킬이 막으려는 실패

실제로 일어나는 순서대로 적었다.

1. **조회 실패를 '위험 없음'으로 읽는 것.** 산사태 API가 403을 반환해 결과가
   비었을 때 "산사태 위험이 없습니다"라고 답하면 위험을 은폐한 것이 된다.
2. **오래된 값을 현재 상황으로 제시하는 것.** 6시간 전 강우량은 지금 강우량이
   아니다.
3. **예보를 관측으로 제시하는 것.** 예보 강우량과 실황 강우량은 다른 값이다.
4. **해제된 특보를 발효 중으로 읽는 것.** "호우주의보 해제"는 위험이 끝났다는
   뜻이다.
5. **집계 통계로 개인을 추정하는 것.** 고령인구 비율이 높다는 사실이 특정
   주민의 보행 곤란을 뜻하지 않는다.
6. **출처 없이 답하는 것.** 근거를 제시할 수 없는 재난 판단은 행정에서 쓸 수 없다.
7. **재난유형이 맞지 않는 대피소를 배정하는 것.** 지진 옥외대피장소는 호우
   대피소가 아니다.
8. **변경금지 데이터를 가공하는 것.** 홍수위험지도는 재투영조차 이용조건 위반이다.

## 절대 규칙

**출처 없이 값을 제시하지 않는다.** 모든 응답에 `citations`가 있다. 답변에
기관명, 데이터셋명, 기준 시각을 밝힌다.

**`complete: false`를 무시하지 않는다.** 일부 원천 조회에 실패한 상태다.
`records`가 비어 있어도 '해당 없음'이 아니다. `warnings`를 읽고 무엇을 확인하지
못했는지 사용자에게 알린다.

**`absence_confirmed`가 답을 결정한다.** 결과가 비어 있을 때 그것을 '위험 없음'으로
말해도 되는지는 이 필드가 정한다.

| `absence_confirmed` | 답변 |
| --- | --- |
| `true` | "확인한 결과 해당 사항이 없습니다"라고 말할 수 있다 |
| `false` | **위험이 없다고 말하면 안 된다.** 확인하지 못했다고 말한다 |

`sources_checked`에 원천별 결과가 있다. `outcome`이 `failed`인 원천은 조회하지
못한 것이므로, 그 원천이 다루는 위험은 확인되지 않았다고 밝힌다.

```
sources_checked:
  weather_warning     records          9건
  landslide_forecast  failed           HTTP 403 개발단계 심의 대기
```

이 경우 "산사태 위험 없음"이 아니라 "산사태 예보는 확인하지 못했다"가 정확한 답이다.

**추측으로 빈칸을 채우지 않는다.** 데이터가 없으면 없다고 답하고 어디서 확인할
수 있는지 안내한다(`gbsafe_describe_dataset`의 `how_to_obtain`).

**대피 결정을 내리지 않는다.** 근거와 후보를 제시한다. 어느 마을을 먼저
대피시킬지, 어느 대피소로 보낼지는 담당 공무원이 검토·승인한다.

**개인을 추정하지 않는다.** 공개 인구통계는 지역 단위 취약성 지표다.

**전화·명령·상태변경을 시도하지 않는다.** 이 데이터 계층에 그런 도구가 없다.
있다면 잘못 설계된 것이다.

## 재난별 확인 순서

호우·산사태가 주 시나리오다. 강우가 산사태의 선행 조건이므로 순서가 중요하다.

| 재난 | 확인 순서 |
| --- | --- |
| 극한호우 | 기상특보 → 실황 강우 → 단기예보 |
| 산사태 | 산사태 예보단계 → 기상특보 → 실황·누적 강우 → 도로변 취약구간 |
| 산불 | 산불위험지수 → 실황 풍속·습도 → 대기질(연무) |
| 침수 | 기상특보 → 실황 강우 → 예보 |

`gbsafe_hazard_context`가 재난 유형에 맞는 원천을 자동으로 선택한다. 개별 원천이
필요하면 `gbsafe_fetch_source`를 쓴다.

## 답변 작성 방법

**좋은 답변의 구조:**

```
문경시에 현재 호우주의보가 발효 중입니다.

- 특보: 호우주의보 (대구지방기상청 관할, 2026-08-21 17:00 발표)
- 실황 강우: 시간당 0mm (2026-08-22 02:00 기준, 1시간 전 관측)

확인하지 못한 것: 산사태 예보단계입니다. 산림청 산사태 예측정보 API가
개발단계 심의 대기 중이어서 조회되지 않았습니다. 산사태 위험이 없다는
뜻이 아니며, 별도로 확인이 필요합니다.

출처: 기상청 「기상청 기상특보」 (공공누리 제1유형), 기준 2026-08-21 17:00
      기상청 「기상청 단기예보」 (공공누리 제1유형), 기준 2026-08-22 02:00
```

핵심은 **확인하지 못한 것을 밝히는 문단**이다. 이것을 빼면 답변이 실제보다
확실해 보인다.

**하지 말아야 할 답변:**

```
문경시는 현재 산사태 위험이 없습니다.        ← 조회 실패를 안전으로 해석
강우량은 15mm입니다.                        ← 언제 값인지 없음
기온은 0℃입니다.                            ← 결측(null)을 0으로 읽음
고령자가 많아 이동 지원이 필요한 주민이 많습니다.  ← 집계로 개인 추정
가장 가까운 마을회관으로 대피하세요.        ← 대피 결정을 AI가 내림
```

**결측은 0이 아니다.** `value`가 `null`이면 관측되지 않은 것이다. 0으로 읽으면
기온 결측이 영하에 가까운 실측처럼 보인다.

## 신선도 판정

각 레코드의 `freshness.usable_for_decision`이 `false`면 판단 근거로 쓰기 전에
시점을 반드시 밝힌다.

| 상태 | 의미 | 대응 |
| --- | --- | --- |
| `fresh` | 갱신주기 2배 이내 | 판단 근거로 사용 가능 |
| `aging` | 갱신주기 2~6배 | **판단 근거로 쓰지 않는다** — 시점을 반드시 표시 |
| `stale` | 갱신주기 6배 초과 | 오래된 자료임을 명시하고 재확인 권고 |
| `unknown` | 관측시각 없음 또는 미래 시각 | 최신성을 보장할 수 없음을 밝힘 |

`aging`이 판단 근거가 아닌 이유는 시간당 갱신 자료라면 최대 6시간 전 값이기
때문이다. 6시간 전 강우를 현재 상황으로 제시하면 대응 시점 판단이 틀어진다.

`unknown`을 `fresh`로 취급하지 않는다. '모른다'와 '최신이다'는 다르다.

## 라이선스 확인

가공을 하기 전에 `gbsafe_verify_dataset`에 `operation="derive"`로 확인한다.

`derive`에 포함되는 것: 재투영, 클리핑, 래스터화, 좌표계 변환, 다른 데이터와
조인, 파생 지표·학습 라벨 생성.

| 라이선스 | 조회 | 가공 | 재배포 | 상업적 |
| --- | --- | --- | --- | --- |
| 제한없음 | O | O | O | O |
| 공공누리 1 | O | O | O | O |
| 공공누리 2 | O | O | O | X |
| 공공누리 3 | O | **X** | O | O |
| 공공누리 4 | O | **X** | O | X |
| ODbL | O | O | O(share-alike) | O |

**변경금지(3·4유형)가 이 프로젝트에서 특히 문제가 된다.** 홍수위험지도 계열이
전부 4유형인데, 대피 분석이 그 데이터로 하려는 일의 대부분이 재투영·클리핑이다.
화면 표시만 가능하다.

**ODbL은 전염된다.** OSM 도로망을 정부 데이터와 병합해 배포하면 출처표시만
요구하던 정부 데이터에도 share-alike가 얹힌다. 산출물을 분리한다.

## 데이터를 믿기 전에

`gbsafe_quality_report`로 확인된 결함을 본다. 포털 메타데이터가 틀린 사례가
반복적으로 확인됐다.

- 전국 소방용수시설: 5만 건 표기, 실제 199,507행 (4배 과소)
- 지진 대피시설 2종: 그리드가 0행 — CSV를 받아도 헤더만 나온다
- 경북 지방도 관리현황: 전체 1행의 빈 등록물
- 경북 파일데이터: CP949 인코딩 (UTF-8로 읽으면 깨진다)

행 수와 갱신일 표기를 근거로 삼기 전에 실제 응답을 확인한다.

## 대피시설을 다룰 때

**`supported_hazards`가 비어 있으면 어떤 재난에도 배정하지 않는다.** 원본에
재난유형이 명시되지 않은 경우이고, 추정해서 채우면 지진 대피소를 호우 대피소로
쓰는 사고가 된다.

함께 표시해야 할 것:

- 공식 지정시설인지 후보시설인지 (`designated`)
- 현재 운영 여부 — `null`은 '운영중'이 아니라 '확인되지 않음'
- 수용인원의 신뢰도 — 확인 시각이 없으면 실시간으로 표시하지 않는다
- 좌표 유무 — 없으면 거리·경로 계산에 쓸 수 없다

## 경로를 다룰 때

현장 검증 전에는 '공식 안전경로'가 아니라 **'대피 후보 경로'**다. 도로망
데이터에 농로·마을길·보행로가 누락될 수 있고, 도보·휠체어·차량은 필요한 정보가
서로 다르다.

## 지역 식별자

기관마다 다르다. `gbsafe_resolve_region`으로 변환한다.

| 원천 | 요구하는 식별자 |
| --- | --- |
| 기상청 단기예보 | 격자 nx/ny (위경도 아님) |
| 기상청 특보 | 발표관서 번호 (경북은 143·136·138) |
| 기상청 ASOS | 지점번호 (문경 137) |
| 대부분의 API | 시군구 코드 5자리 (문경 47280) |

**`gbsafe_resolve_region`은 경북 시군만 받는다.** 다른 지역을 물으면 실패하는 것이
정상이며, 이 인프라의 대상 범위가 경북이기 때문이다.

**군위군(47720)은 2023년 대구광역시로 편입됐다.** 옛 자료에 경북으로 남아 있으면
시점을 확인한다. 이름(`군위군`)으로 물어도 코드(`47720`)로 물어도 편입 사실을
알려준다.
