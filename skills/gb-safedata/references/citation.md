# 인용 형식과 답변 템플릿

## 왜 형식을 정하는가

재난 판단은 사후에 검증된다. "그때 왜 그 마을을 먼저 대피시켰는가"에 답하려면
판단에 쓴 데이터가 무엇이고 몇 시 기준이었는지 남아 있어야 한다. 인용은 예의가
아니라 감사 요건이다.

## 최소 인용 단위

응답의 `citations[].text`가 이미 완성된 형태다. 그대로 쓴다.

```
기상청 「기상청 기상특보」 · 기준 2026-08-21T17:00:00+09:00 · KOGL-1 · https://www.data.go.kr/data/15000415/openapi.do
```

구성 요소:

| 요소 | 이유 |
| --- | --- |
| 기관명 | 책임 소재 |
| 데이터셋명 | 같은 기관이 여러 데이터를 제공한다 |
| 기준 시각 | 관측·발표 시각. 조회 시각이 아니다 |
| 라이선스 | 출처표시 의무가 있는지 |
| 원본 링크 | 사람이 직접 확인할 수 있어야 한다 |

**기준 시각은 `observed_at` > `published_at` > `retrieved_at` 순으로 신뢰한다.**
조회 시각을 관측 시각처럼 쓰면 6시간 전 데이터가 방금 것으로 보인다.

## 답변 템플릿

### 위험 상황 답변

```
{지역}에 현재 {상황}입니다.

- {항목}: {값} ({기관}, {기준시각} 기준{, 예보인 경우 "예보값" 명시})
- {항목}: {값} ({기관}, {기준시각} 기준)

확인하지 못한 것: {원천명}입니다. {사유}. {그것이 안전을 의미하지 않는다는 설명}.

출처:
  {citations[].text}
```

`확인하지 못한 것` 문단은 `complete`가 `false`일 때 **필수**다. 빼면 답변이 실제보다
확실해 보인다.

### 데이터셋 안내 답변

```
{용도}에 쓸 수 있는 데이터는 {개수}건입니다.

1. {데이터셋명} ({ID})
   - 제공: {기관}
   - 취득: {how_to_obtain}
   - 라이선스: {license_summary}
   - 지금 호출 가능: {예/아니오 + 사유}
   - 주의: {quality_flags 또는 caveat}
```

`dev_ready`가 `false`인 항목은 **"라이선스는 허용하지만 지금 호출할 수 없다"**고
명확히 구별한다. 두 가지가 다른 문제이고 대응도 다르다.

### 라이선스 판정 답변

```
{데이터셋명}을 {용도}에 사용하는 것은 {허용/불가}입니다.

라이선스: {license_summary}
근거: {reasons}
주의: {warnings}
```

## 하지 말아야 할 것

**출처를 요약하지 않는다.**

```
나쁨: 공공데이터포털 자료에 따르면
좋음: 기상청 「기상청 기상특보」, 기준 2026-08-21 17:00
```

포털은 원천이 아니라 카탈로그다. 91건 중 33건은 포털이 데이터를 갖고 있지도 않다.

**시각을 생략하지 않는다.**

```
나쁨: 현재 강우량은 15mm입니다
좋음: 2026-08-22 02:00 관측 강우량은 15mm입니다 (1시간 전)
```

**예보와 관측을 섞지 않는다.**

`is_forecast: true`인 값은 "예보"라고 밝힌다. 예보 강우량을 현재 강우량으로
제시하면 대응 시점 판단이 틀어진다.

**모드를 숨기지 않는다.**

`source.mode`가 `synthetic`이면 훈련 데이터다. 답변 앞머리에 훈련임을 밝힌다.
`snapshot`이면 캐시된 과거 응답이므로 그 사실을 밝힌다.

## 여러 원천을 합칠 때

각 값마다 출처가 다르므로 값 옆에 출처를 붙인다. 답변 끝에 출처를 모아 놓기만
하면 어느 값이 어디서 왔는지 알 수 없다.

```
나쁨:
  강우 15mm, 산사태 주의보 발효, 대피소 3곳 가용
  출처: 기상청, 산림청, 행정안전부

좋음:
  - 강우 15mm (기상청 단기예보, 2026-08-22 02:00 관측)
  - 산사태 주의보 (산림청 산사태 예측정보, 2026-08-22 01:00 발표)
  - 대피소 3곳 (행정안전부 대피시설 현황, 2026-06-05 갱신 — 현재 운영 여부 미확인)
```

세 번째 항목처럼 **데이터의 한계를 값과 함께** 적는다.
