# 라이선스별 허용 연산

## 판단 절차

가공을 시작하기 전에 확인한다. 나중에 확인하면 이미 위반한 상태가 된다.

```
gbsafe_verify_dataset(dataset_id, operation="derive")
```

`allowed: false`면 그 데이터로 재투영·클리핑·조인을 하지 않는다.

## 연산 정의

용어가 모호해서 위반이 생긴다. 이 프로젝트에서는 다음으로 정한다.

| 연산 | 포함되는 것 |
| --- | --- |
| `read` | 조회, 화면 표시, 원본 그대로 인용 |
| `derive` | 재투영, 클리핑, 래스터화, 좌표계 변환, 다른 데이터와 조인, 파생 지표 계산, 학습 라벨 생성, 포맷 변환 |
| `redistribute` | 원본 또는 가공본을 저장소·산출물에 담아 배포 |
| `commercial` | 상업적 이용 |

**포맷 변환이 `derive`에 들어가는 것이 중요하다.** SHP를 GeoJSON으로 바꾸는 것도
변경금지 조항에 걸린다.

## 라이선스별 허용

| 라이선스 | read | derive | redistribute | commercial | 출처표시 |
| --- | --- | --- | --- | --- | --- |
| 제한없음 | O | O | O | O | 불필요 |
| 공공누리 1 | O | O | O | O | 필요 |
| 공공누리 2 | O | O | O | **X** | 필요 |
| 공공누리 3 | O | **X** | O | O | 필요 |
| 공공누리 4 | O | **X** | O | **X** | 필요 |
| ODbL | O | O | O(share-alike) | O | 필요 |
| 미확인 | O | **X** | **X** | **X** | 필요 |

**미확인은 조회만 허용한다.** 관대하게 추정해서 통과시키는 것보다 막고 확인하게
하는 편이 안전하다.

## 이 프로젝트에서 실제로 문제가 되는 것

### 변경금지 — 홍수 계열 전체

홍수위험지도 계열 21종이 **공공누리 제4유형**이다. 출처표시 + 상업적 이용금지 +
변경금지다.

변경금지가 막는 것:

- EPSG:5186 → EPSG:4326 재투영 (좌표계를 맞추는 것)
- 경북 영역만 잘라내기 (클리핑)
- 벡터를 래스터로 변환
- 침수 위험 등급을 마을 단위로 집계
- 대피 모델 학습 라벨 생성

즉 **대피 분석이 그 데이터로 하려는 일의 대부분**이다. 화면에 그대로 띄우는 것만
가능하다.

AirKorea(대기오염정보)는 제3유형이다. 변경금지이지만 상업적 이용은 가능하다.

### share-alike 전염 — OSM

ODbL은 share-alike다. 가공한 OSM 데이터를 커밋해 배포하면 그 데이터가 ODbL이 된다.

**특히 위험한 조합:** OSM 도로망과 공공누리 1유형 정부 데이터를 병합해 하나의
산출물로 배포하면, 출처표시만 요구하던 정부 데이터에도 share-alike가 얹힌다.

대응: 산출물을 분리한다. 전처리 스크립트만 배포하고 가공된 데이터는 담지 않는다.

### 상업적 이용금지와 오픈소스의 충돌

공공누리 2·4유형의 상업적 이용금지는 **이용 분야를 차별할 수 없는 OSI 계열
오픈소스 라이선스와 양립하지 않는다.** Apache-2.0으로 배포하는 저장소에 4유형
데이터를 넣으면 라이선스가 서로 모순된다.

대응: 데이터를 저장소에 담지 않고 취득 방법만 제공한다.

## 출처표시 문구

`source.attribution`에 완성된 문구가 온다.

```
출처: 기상청 「기상청 기상특보」 (공공누리 제1유형 — 출처표시)
```

출처표시 의무가 없는 경우(제한없음)에는 `attribution`이 `null`이다. 그래도 인용은
한다 — 의무가 아니라 검증 가능성 때문이다.

## 여러 라이선스를 합칠 때

`redistribution_contamination()`이 문제를 알려준다.

확인하는 것:

1. 재배포가 금지된 라이선스가 섞여 있는지
2. share-alike와 그렇지 않은 것이 섞여 있는지

둘 중 하나라도 해당되면 산출물을 분리해야 한다.
