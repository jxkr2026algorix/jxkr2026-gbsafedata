# 기관별 API 함정과 데이터 결함

실제 호출·다운로드로 확인된 것만 적었다.

## 호출 함정

### 서비스키 파라미터 이름이 기관마다 다르다

| 표기 | 기관 |
| --- | --- |
| `ServiceKey` (대문자 S) | 기상청, 산림청, 국립중앙의료원 문서 표기 |
| `serviceKey` (소문자 s) | AirKorea, TAGO |

실제로는 소문자 `serviceKey`가 대부분 통과한다. 401이 나면 이것을 먼저 확인한다.

### 응답 포맷 파라미터가 세 갈래다

| 파라미터 | 기관 |
| --- | --- |
| `dataType` | 기상청 |
| `returnType` | AirKorea |
| `_type` | 산림청, TAGO |
| (없음 — XML만) | 국립중앙의료원, 산림청 산불발생통계 |

**응급의료는 XML만 반환한다.** JSON을 기대하고 파싱하면 실패한다.

### 오류가 HTTP 200 본문에 온다

포털 게이트웨이는 인증 실패도 200으로 돌려주고 본문에 담는다.

```xml
<returnReasonCode>30</returnReasonCode>
<returnAuthMsg>SERVICE_KEY_IS_NOT_REGISTERED_ERROR</returnAuthMsg>
```

또는 JSON `resultCode`가 `00`이 아닌 값으로 온다. 상태코드만 보면 성공으로 읽힌다.

### 403의 의미가 셋이다

같은 403이 다른 원인을 갖는다.

1. 인증키가 아직 활성화되지 않음 (신청 후 최대 1시간)
2. **개발단계 심의승인 대기** — 승인 전까지 계속 막힌다
3. 이 데이터셋에 활용신청을 하지 않음

산림청 산사태 3종(15074800, 15074812, 15074816)이 2번이다. 개발단계가 심의승인이고
운영단계가 자동승인인 **역방향** 구조라서, 키를 다시 발급받아도 해결되지 않는다.

### 호스트가 하나가 아니다

대부분 `apis.data.go.kr`이지만 예외가 있다.

| 데이터 | 실제 호스트 |
| --- | --- |
| 기상청 레이더·천리안2A | `apihub.kma.go.kr` (별도 authKey) |
| 주민등록 인구 | `rdoa.jumin.go.kr` (포털 키를 인식하지 않음) |
| 산불위험예보 | `apis.data.go.kr/1400377/` (다른 산림청 API는 `/1400000/`) |

### 개발계정 호출 한도가 다르다

| API | 일 한도 |
| --- | --- |
| AirKorea | **500** |
| 산불위험예보, 응급의료 | 1,000 |
| 나머지 | 10,000 |

AirKorea는 다른 API의 20분의 1이므로 폴링 주기를 따로 잡아야 한다. 간헐적으로
504도 반환하는데 재시도하면 응답한다.

### 91건 중 33건은 포털에서 호출되지 않는다

REST로 등록되어 있어도 `API 유형 LINK`이면 포털은 카탈로그 역할만 한다. 인증키는
원천기관에서 별도로 받아야 한다.

| 원천기관 포털 | 대상 |
| --- | --- |
| 기상청 API허브 | 레이더, 천리안2A, AWS |
| 한강홍수통제소 | 수위, 유량, 홍수특보 |
| 재난안전데이터 공유플랫폼 | 급경사지, 대피공간, 병상 |
| 생활안전지도 | 침수흔적도, 산불발생이력 |
| ITS / UTIC | 돌발·통제정보 |

`gbsafe_describe_dataset`의 `how_to_obtain`이 어느 포털인지 알려준다.

## 데이터 결함

### 행 수를 믿을 수 없다

| 데이터셋 | 표기 | 실제 |
| --- | --- | --- |
| 전국 소방용수시설 (15034538) | 50,000 | **199,507** (4배 과소) |
| 초단기 침수위험 예측알람 (15152508) | 1 | 100 |
| 경북 지방도 관리현황 (15153591) | 1 | **빈 등록물** |

50,000은 실제 행 수가 아니라 **그리드 다운로드 상한**이다.

### 아예 빈 데이터셋

| 데이터셋 | 상태 |
| --- | --- |
| 지진 옥외대피장소 (15072620) | 그리드 0행 — CSV를 받아도 헤더만 |
| 지진겸용 임시주거시설 (15072622) | 그리드 0행 |

둘 다 `safetydata.go.kr` 경유가 필요하다.

### 확장자 표기가 틀린다

15152508은 CSV로 표기되지만 실제로는 ZIP이고, 내부 코드북이 본 데이터의 64배다.

### 인코딩

**경북 파일데이터는 CP949다.** UTF-8로 읽으면 깨진다. `decode_csv()`가 자동
판별하지만, 직접 읽을 때는 `cp949` 또는 `euc-kr`을 시도해야 한다.

### 갱신 표기와 내용이 다르다

15013199는 수정일이 2024-09-27인데 첫 레코드 기준일자가 2018-05-15다. 수정일을
데이터 시점으로 믿으면 6년 된 데이터를 최신으로 취급한다.

### 좌표가 없거나 다른 좌표계다

경북 산사태취약지역 8,187행 중 좌표가 있는 것은 일부다. 문경시(15123407) 451행은
좌표가 포함되어 있다.

**위경도 컬럼에 EPSG:5179/5186 값이 들어간 경우가 있다.** 범위를 벗어나는 값은
`GeoPoint`가 거부하고 `coordinate_out_of_range` 플래그가 남는다.

### 행정구역 개편

**군위군(47720)은 2023-07-01 대구광역시로 편입됐다.** 경북 자료에 남아 있으면
데이터 시점을 확인한다.

## 기상청 격자 좌표

**nx/ny는 위경도가 아니다.** Lambert Conformal Conic 변환이 필요하고, 변환식은
공개 페이지에 없고 첨부 ZIP에만 있다.

`gbsafe_resolve_region`이 변환해 준다. **이 도구는 경북 시군만 받는다** — 다른
지역을 물으면 "경북 시군으로 해석할 수 없습니다"가 나오는 것이 정상이다.

변환식 자체를 검증하려면 `gbsafe_core.regions.to_kma_grid()`를 직접 호출한다.
공개된 기준값은 다음과 같다.

| 지점 | 위경도 | 격자 |
| --- | --- | --- |
| 서울 | 37.5665, 126.9780 | 60, 127 |
| 부산 | 35.1796, 129.0756 | 98, 76 |
| 제주 | 33.4996, 126.5312 | 53, 38 |
| 문경 | 36.5866, 128.1867 | 81, 106 |

```python
from gbsafe_core.models import GeoPoint
from gbsafe_core.regions import to_kma_grid
to_kma_grid(GeoPoint(lat=37.5665, lon=126.9780))   # nx=60 ny=127
```

**잘못된 격자를 넣어도 API는 200과 그럴듯한 값을 반환한다.** 다른 도시의 날씨를
읽으면서 성공한 것처럼 보이므로, 격자값은 역변환으로 검증해야 한다.

## 특보 조회

기상특보 목록 API는 지역명이 아니라 **발표관서 번호**를 준다.

| 번호 | 관서 |
| --- | --- |
| 108 | 기상청 본청 (전국) |
| 143 | 대구지방기상청 (대구·경북) |
| 136 | 안동기상대 (경북 북부내륙) |
| 138 | 포항기상대 (경북 동해안) |

**필터하지 않으면 전국 특보가 경북 특보처럼 섞인다.** 실제 조회에서 100건 중 83건이
타 지역이었다.

## 시점 필드

| 필드 | 의미 |
| --- | --- |
| `retrieved_at` | GB SafeData가 조회한 시각 |
| `observed_at` | 원천의 관측 시각 |
| `published_at` | 원천의 발표 시각 |

**신선도는 `observed_at` > `published_at` > `retrieved_at` 순으로 판단한다.**
응급의료의 `hvidate`가 실제 갱신 시각이므로 이 값 없이 병상 수를 실시간처럼
표시하면 안 된다.
